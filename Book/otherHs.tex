\chapter{Haskell practicalities}
\label{OtherHS}
\index{Haskell!implementations}
\index{Haskell Platform}

Chapter \ref{getStart} covered the recommended way to get going with Haskell: installing GHC, \texttt{cabal} and the Haskell Language Server using GHCup, and then obtaining the code for this book from either Hackage or GitHub. This appendix covers the alternatives: other ways to install Haskell locally, and -- often more useful for a reader who just wants to try something out first -- several ways of running Haskell \emph{without} installing anything at all.

\subsection*{Installing Haskell locally}
\index{GHCup}

GHCup, \url{https://www.haskell.org/ghcup/}, described in Chapter \ref{getStart}, is the toolchain installer that \texttt{haskell.org} itself recommends, and remains the best starting point on Linux, macOS and Windows (native or under WSL). A system package manager -- Homebrew's \texttt{ghc} and \texttt{cabal-install} on macOS, \texttt{apt} on Debian/Ubuntu, Chocolatey on Windows -- can also install a Haskell toolchain, but the versions provided are often out of date, so GHCup remains the better default. Readers who prefer the Stack build tool to Cabal can instead run \texttt{stack setup}\index{Stack}, which fetches and manages its own GHC.

Readers who would rather not install anything directly onto their own machine, but who already have Docker\index{Docker} installed for other reasons, can use the official Haskell Docker image instead:
\begin{alltt}
docker run -it haskell:9.6 ghci
\end{alltt}
This gives a disposable GHC, \texttt{cabal} and Stack installation inside a container, with no risk of it clashing with anything else already on the machine.

\subsection*{Running Haskell with nothing installed}
\index{Codespaces}\index{Gitpod}

For a reader who wants to try the book's actual code -- including its multi-module structure and dependencies such as \texttt{QuickCheck} -- without installing anything, the best option is a cloud development environment. This book's GitHub repository includes a \emph{dev container} configuration which builds a ready-to-use GHC, \texttt{cabal} and HLS environment with the code for the book already built. It can be used in a few ways:
\begin{itemize}
\item \textbf{GitHub Codespaces}\index{Codespaces}: on the repository's GitHub page, \url{https://github.com/simonjohnthompson/haskellcraft}, click \textbf{Code}, then the \textbf{Codespaces} tab, then \textbf{Create codespace on main}. This opens a full, browser-based copy of VS Code, already connected to a virtual machine with Haskell installed; GitHub gives every personal account a free monthly quota of Codespaces hours.
\item \textbf{Gitpod}\index{Gitpod} reads the same configuration file, and can be used by visiting \url{https://gitpod.io/#https://github.com/simonjohnthompson/haskellcraft}.
\item With Docker and VS Code's \textbf{Dev Containers} extension installed locally, opening a clone of the repository and choosing \textbf{Reopen in Container} uses the same configuration, without needing either service above.
\end{itemize}
In each case, once the container has finished building -- the first time takes a few minutes, so watch for the ``Running postCreateCommand'' notification to complete -- opening a terminal and typing \texttt{cabal repl} gives a working \texttt{ghci} prompt with all of the book's code and dependencies available, exactly as described in Section \ref{multipleModuleProgs}; opening a \texttt{.hs} file gives the usual IDE features through HLS.

For trying out a single short expression or function, rather than the book's code as a whole, an online \textbf{playground}\index{playground} may be quicker still. The current, officially maintained one is \url{https://play.haskell.org}; it compiles a single file containing a \texttt{main} function and produces a shareable link, but does not support GHCi-style interaction or the book's package dependencies. (An older, once widely-recommended site, \texttt{tryhaskell.org}, closed in 2025 after sixteen years of service; if you see it mentioned elsewhere, use \texttt{play.haskell.org} instead.) A number of general-purpose online IDEs -- Replit, JDoodle, OneCompiler and others -- also support Haskell to varying degrees, and may be convenient if you already use one of these for other purposes, though none is Haskell-specific.

Two further approaches are worth knowing about, though neither is yet a good fit for this book. Since version 9.6, GHC has had an experimental WebAssembly backend, and a public demonstration, \url{https://haskell-wasm.github.io/ghc-in-browser/}, runs GHC itself inside the browser tab with no server involved at all; today, though, it supports no external packages and so cannot build the book's code. Jupyter notebooks can also be used for Haskell via the \textbf{IHaskell}\index{IHaskell} kernel, and a repository can be made launchable with no installation using \url{https://mybinder.org}; this gives a capable, genuine environment, but with a much slower start-up than the dev container described above, so it isn't needed here.

\subsection*{Editors and IDEs for Haskell}
\index{editors for Haskell}

As discussed in Chapter \ref{getStart}, Visual Studio Code together with the Haskell Language Server (HLS) is a good default choice: it is free, cross-platform, and provides type checking, refactoring and other IDE features once the \texttt{haskell.haskell} extension is installed. Several other editors have long-standing Haskell support, and remain popular with readers who prefer a terminal-based workflow: emacs, via its Haskell mode, \url{https://github.com/haskell/haskell-mode}; and vim, via \url{https://github.com/neovimhaskell/haskell-vim}. An overview of editor support more generally can be found at
\begin{alltt}
https://wiki.haskell.org/Editors
\end{alltt}
